# 界面设计

当前实现是原生 Rust / egui 桌面界面，入口见 [desktop.rs](crates/gui/src/desktop.rs)、[appearance.rs](crates/gui/src/appearance.rs) 和 [main.rs](crates/gui/src/main.rs)。产品范围见 [PRODUCT.md](PRODUCT.md)。这里记录界面的实现约定，硬件兼容与测试结论分别以对应验收记录为准。

## 视觉方向与参考

用户明确要求“磨砂、极简、留白、艺术字”，以石墨深色为主，不使用蓝色。最新细化要求将设备状态放在首位：缩小标题、收紧散热面板、减轻雾感，保留清楚的文字层级与必要反馈。艺术字体收敛到小尺寸品牌字。旧的 Cyber-HUD 和固定侧栏布局已不再作为设计方向。

本轮可核查的参考来自设计师本人公开的网站：

- [Rauno Freiberg · Designing Depth](https://rauno.me/craft/depth)：参考其通过前后层次、背景虚化与边界处理建立深度的思路。
- [Emil Kowalski](https://emilkowal.ski/)：参考其公开交互作品对界面反馈与细节的处理。

用户所说的 X 上设计师作品是参考方向；上述链接是实际查阅的公开来源，不表示已经查看受限的 X 帖子，也不表示照搬某位设计师的完整界面。

## 材质与颜色

页面使用应用内部绘制的柔和背景，只保留右上角的一团淡暖光，去除绿色光晕，颗粒强度降为原来的四分之一。纹理按主题缓存，不逐帧变化，不依赖传感器输入。面板使用接近不透明的均匀灰色填充、细边、极轻的上沿反光与阴影，减轻大片灰雾感。实现不截取桌面，也不调用操作系统的桌面背景模糊。

| 用途 | 石墨主题 | 浅色主题 |
| --- | --- | --- |
| 基础页面背景 | `#171818` | `#F1F0E9` |
| 磨砂面板填充 | `rgba(34,35,36,239/255)` | `rgba(252,252,249,240/255)` |
| 主文字／温度值 | `#F6F6F3` | `#252723` |
| CPU／GPU／风扇名称 | `#D1D3D4` | `#44484B` |
| 次要文字 | `#A4A7A9` | `#676A6C` |
| CPU 曲线／确认反馈 | `#A7C08C` | `#45692C` |
| GPU 曲线／等待反馈 | `#DDBB7C` | `#89641F` |
| 错误反馈 | `#ED9A8C` | `#9A2E22` |

默认使用石墨主题，也可选择浅色或跟随系统。绿与琥珀用于读数区分与必要反馈；页面不以大面积高饱和色装饰运行状态。磨砂面板圆角为 20，内边距通常为 24，可用宽度不足 380 时为 18。数值均为逻辑单位，实际颜色包含背景与透明层的混合，以源码为准。

## 字体与留白

[字体资产目录](crates/gui/assets/fonts/README.md)随程序嵌入 Cormorant Garamond Italic 和 Manrope，并保留各自的 SIL Open Font License 1.1。运行时不下载字体。

- 页标题改为“设备概览”“传感器”“型号目录”，字号统一为 34。设备型号与更新时间在宽屏放在标题旁边，窄屏自然下移；不再显示占据大面积的英文标题、装饰眉题与重复副标题。
- Cormorant Garamond Italic 仅用于顶部 19 字号的 `MECHREVO` 品牌字。Manrope 用于拉丁界面文字与温度单位。两份可变字体通过字体坐标显式设置 `wght` 轴：Cormorant 为 400，Manrope 为 450。中文继续由操作系统字体提供器补全。
- 温度与风扇数值使用 egui 的真实等宽字体，字号分别为 52 与 18；相同位数的读数变化保持宽度，避免比例数字造成左右跳动。温度单位为 18。这里不把 Manrope 的比例数字当作等宽数字。
- 正文与按钮默认 14、次要文字 13，主要标签与辅助说明采用 13–14；文字缩放范围为 80–160%。常规控件最小交互高度 36、圆角 8，导航圆角为 9。
- 主内容宽度最多 1000，居中排布；窗口宽度至少为 900 时外边距为 40，更窄时为 16。留白用于区分标题、主要读数和操作区，不增加空白的装饰模块。

## 布局与组件

- 默认主窗为 1120×760，最小尺寸为 360×280。顶部使用品牌、概览／传感器／型号目录导航及刷新／采样／显示设置操作，允许随宽度换行；主内容纵向滚动。导航采用文字与浅色选中底，不使用胶囊边框；自动采样使用独立的小开关。
- 页标题旁显示设备名称、平台与更新时间；主内容宽度不足 660 时下移。长设备名采用单行省略，悬停可看全名及主板，设备详情保留原始值。导航与标题、标题与散热面板之间各保留 12 的间隔，使读数更早进入视线。
- 概览先显示占满内容宽度的温度与散热面板。面板内部宽度至少为 720 时，CPU／GPU 双读数在左侧，真实温度趋势在右侧，按约 46%／54% 分配宽度，列间距为 28；趋势区高度为 108。标准桌面视图的面板最小总高度为 270，大字体或额外传感器可自然撑高，不通过裁切强制固定高度。更窄时改为读数在上、趋势在下，两组温度在内部宽度不足 280 时继续上下排列。
- 系统电源策略与屏幕亮度位于散热面板下方；主内容宽度至少为 660 时并排，两张卡片之间留出 18 的间隔，卡内横向间距恢复为常规的 10；窄屏改为上下排列。不可用项保留简短原因与“查看原因”展开入口，不显示整排不可操作的按钮或滑块。
- 供电与电池、设备识别信息继续向下排布。接口限制、操作范围和技术路径保留在可展开详情中。
- 首页 CPU／GPU 分别显示同类当前最高的有效温度。悬停主读数可查标签、设备与路径；这只是按读数来源分组，不推断物理热管或硬件拓扑。
- 只有传感器标签明确包含单独的 `CPU` 或 `GPU` 名称、且不同时包含两者时，风扇才放在相应温度下方。`fan1`、`fan2`、设备顺序与共享路径不能确定归属，这类读数保留在面板底部，宽度至少为 520 时并排，更窄时逐项排列。CPU、GPU、未归属三个组各最多显示三个风扇，省略数量有提示，其余读数在传感器页查看。未归属风扇标签仅在开头匹配已知的 `mechrevo_ec:` 前缀时将其去掉，悬停仍显示完整原始标签，来源不变。
- CPU／GPU 名称前的小标记与文字保留 6 的项间距，去掉重复的“当前最高读数”说明，来源信息留在悬停内容。传感器页的名称与来源允许换行，并可一次展开全部来源，包含设备标识、后端、路径及不可用原因。型号目录只表示官方公开产品条目，不授予控制能力。

## 真实采样与反馈

“自动采样”默认开启，可关闭。启动时立即提交首次只读刷新，此后距上次成功快照至少 3 秒且条件允许时再次提交。已有后台任务、待确认的电源或亮度预览、后台不可用或正在延后关窗时，不自动提交刷新。单个后台任务处理设备读取，重复请求不会堆积。

自动采样开启时，设备状态显示“刚刚更新”或距上次采样的秒数。关闭后，已有快照显示静态的“已采集 · 手动更新”，避免没有空闲重绘时让秒数停在旧值；手动模式不为更新时间增加周期重绘。

温度趋势只保存本次进程中的真实采样，每个来源最多保留 120 个点。机器身份由厂商、产品、主板、BIOS 与平台组成，身份变化会清空旧历史；来源按设备 ID、读数 ID、后端、路径和单位隔离。缺失、不可用或非有限读数形成断点，不补零、不补齐历史。各条来源曲线至少有三次有效采样才绘制；两条都不足三次时显示“正在积累趋势”，并说明需采集至少三次。

曲线显示当前所选 CPU／GPU 读数来源各自的历史。当前最高来源变化时，显示新来源已有的采样，不拼接其他来源的数值。曲线横轴使用实际采样时间，图下显示所覆盖的秒数或分秒范围。颜色与主读数标记对应，曲线末端有标记，图上方同步显示当前 CPU／GPU 数值；当前来源缺失时显示“—”，不把历史最后一个有效值冒充当前末端值。

导航选中状态有 200 ms 的过渡，常规控件为 180 ms，采样开关为 160 ms；后台忙碌时刷新图标旋转，并显示采集状态。开关保留键盘焦点、点击与开关状态的无障碍语义。关闭“界面过渡动画”会取消这些过渡与旋转，状态文字仍可读。后台任务期间按 80 ms 请求界面重绘；自动采样开启且空闲时按 1 秒请求重绘，这不表示每秒读取硬件。

## 操作与持久化

系统电源策略和屏幕亮度仍按预览、显式应用、后端重新校验、回读及必要恢复的事务流程执行。请求值、驱动报告值与失败／恢复结果分开呈现。切换目标或手动刷新会作废已有计划，应用计划只可使用一次。写入、回读或恢复未结束时，原生关窗请求会延后，事务结束后退出。

标准／紧凑、主题、文字缩放、自动采样和动画偏好保存在 eframe 的系统用户配置目录；操作计划与温度历史不持久化。当前紧凑模式只省去型号目录的“收录说明”，布局仍按可用尺寸调整。

## 当前边界

OEM 性能模式、EC 控制、风扇曲线、MUX、RGB 与水冷控制尚未实现，不能从界面或官方目录推断兼容。风扇读数、声学诊断与实际调速是不同能力；本次界面修改不代表已经完成风扇噪声抑制。Windows 已有交叉编译链接记录，尚无实机硬件写入验收。本轮视觉实现的测试与截图应另外记录，不把既有测试结果直接沿用为本轮通过。
