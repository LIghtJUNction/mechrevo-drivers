# 机械革命控制台

## Platform

Native desktop: Windows and Linux. The renderer is Rust egui, not a web page.

## Users

机械革命笔记本用户，需要查看温度、风扇和供电状态，并调整系统及已识别厂商驱动实际提供的控制项。Windows 与 Linux 的完整控制能力持续按 [OEM 功能覆盖](../docs/OEM-FEATURE-COVERAGE.md) 推进。

## Product Purpose

让用户迅速了解电脑正在怎样运行，找到可用的控制项，并在应用后看到实际回读结果。

## Capabilities and Constraints

- 独立 Rust workspace，GUI 与 CLI 共用核心。现有后端与操作预览、回读、恢复流程必须保留。
- 温度与风扇来自实际传感器；缺失、睡眠和未知不能伪造成零。趋势只能由真实采样构成。
- 官方型号目录不代表硬件控制兼容。Linux OEM 源码候选已接入固定驱动接口上的 Fn 锁、充电档位、键盘亮度及单区 RGB；接电开机与关机 USB 供电只在真实接口存在时列出，本机未暴露。风扇曲线、MUX、水冷及 Windows OEM 后端仍待完成，完整目标不因当前缺口而缩减。
- 本轮 OEM 源码已通过本地检查和四项控制的可逆写入／驱动回读验收，见 [OEM 收据](../docs/verification/oem-controls.json)。安装、驱动加载和实体效果分别记录，不能沿用历史结果。
- GUI“控制”页与 CLI 共用枚举、预览、显式应用、回读及条件恢复。普通用户的 Linux 硬件写入通过受限 helper 请求授权，发现与预览不提权；不要求整个应用以 root 运行或放宽 sysfs 全局写权限。
- 充电档位仅报告驱动给出的选项，不推定 60%／80% 阈值。Fn 与充电回读是 EC 经驱动报告的状态，LED 回读是请求状态缓存；实际按键、停充、发光与持久化需另行验收。
- 原生窗口可缩放，高 DPI、长设备名和大字体下仍需可操作。
- Windows 已有编译检查，Linux 候选原生窗口已打开并核对控制页；这些记录不等于 Windows 实机验收或实体硬件效果。
- 风扇噪声诊断与实际调速分开处理。显示转速、分析录音或修改界面都不代表已经消除异响，不以未经核验的寄存器或风扇参数补齐功能。

## Brand Commitments

- 用户已否定旧的紫青色 Cyber-HUD 和上一轮平面仪表盘；当前方向为磨砂、极简、留白、艺术字。最新细化将设备状态放在首位：34 字号的中文页标题、靠近读数的风扇信息、紧凑的散热面板和可读的辅助说明。
- 石墨深色为默认主题，不使用蓝色；温度数字接近白色，名称使用清楚的浅灰，辅助说明再暗一级。鼠尾草绿和琥珀只承担读数与反馈区分，不绘制绿色背景光晕。
- 参考 X 上优秀设计师作品的完成度；实际查阅的公开参考为 [Rauno Freiberg 的层次设计文章](https://rauno.me/craft/depth)和 [Emil Kowalski 的公开作品](https://emilkowal.ski/)，不声称查看了受限 X 帖子。
- 磨砂观感来自应用内部右上角的淡暖光、极弱的静态颗粒、均匀深灰面板、细边与轻微顶部亮边；卡片圆角统一为 20，不依赖桌面背景捕获或系统模糊效果。
- 艺术字体只用于小尺寸品牌字；内嵌 Cormorant Garamond Italic 和 Manrope 并附带许可证，可变字体字重分别固定为 400 和 450。中文由系统字体补全，温度和转速使用真实等宽字体，运行时不下载字体。
- 用户要求系统活一点：真实读数变化、短交互过渡和明确刷新反馈；不能用假数据、循环噪点或无关的持续动画装饰运行状态。
- 简体中文为主要界面语言，使用正常简洁的表达。

## Product Principles

- 首页回答电脑当前状态以及用户现在能做什么。
- 技术详情随时可查，路径和诊断不占据默认首页。
- 有限的颜色表达状态，留白与字体建立层级。
- 顶部采用文字导航与浅色选中底，自动采样使用小开关。紧凑标题旁显示型号与更新时间，其下直接呈现全宽散热面板：宽屏采用左侧双温度、右侧趋势；标签明确标注 CPU 或 GPU 的风扇靠近对应温度，归属不明的风扇保留在面板底部。控制项继续排在面板下方，窄窗口按内容顺序收拢。
- 趋势由至少三次有效采样积累而来，附上真实时间范围和当前数值；数据不足时明确显示“正在积累趋势”，缺失时保留断点，不用虚构数据填满图表。
- 不可用功能给出简短解释并允许展开原因，避免用大片禁用控件占据主要空间。
- “控制”页按这台设备实际枚举的能力排布；目标调整后先预览，再明确应用。失败、恢复和结果未知分别显示，不以旧缓存、静默重试或重放旧计划冒充成功。
- 交互反馈有生命力，未刷新时不制造运行活动。
