# 整表风扇控制

这组接口提供整表提交、原表恢复、前台 CLI 和原生曲线编辑器。源码验证、软件包安装、运行中驱动身份与风扇实机验收是不同的结果；具体部署状态以对应的验证收据为准，不能据此声称异响已经修复。

2026-10-18 已在本机安装驱动 `4.24.0.r162.ge4bfb3f-1` 和控制台 `0.1.0.r163.g58e8d9c-1`，签名启动镜像及菜单摘要已经更新，旧版恢复入口保留。安装载荷、权限、模块签名及只读启动检查通过；尚未重启，新驱动尚未加载，也没有执行真实风扇接管、曲线应用或恢复。[本次部署收据](verification/deployment-fan-r162-r163.json)

可以从应用菜单打开“机械革命控制台”，或运行 `mechrevo-console-gui`。当前旧接口返回零能力且没有实时曲线表，不能据此启用应用按钮。重启后仍需先核对运行中的模块与接口资格，再进行独立的实机曲线和噪声验收；原有风扇与功耗配置没有由本次安装改写。

现有 TCC 接口修改即时目标值，Linux 驱动会为此建立简化风扇表。返回 AUTO 只释放控制位，不会恢复接管前的完整旧表。新的接口把原始快照、独占控制、整表提交和验证恢复放在同一个驱动所有权范围中。

## 协议与恢复

协议依据见 [OEM 原始写入链](OEM-MIGRATION-NEXT.md#本机布局分支已经闭合)。每个风扇有 16 档原始占空比、15 个升温边界和 15 个降温边界；每次提交写入 94 个表字节，快照保存全部 96 个字节。

CPU 使用 `0x0f00..0x0f2f`，GPU 使用 `0x0f30..0x0f5f`。OEM 正常写入不包含 `0x0f10` 和 `0x0f40`，新接口同样不改这两个字节，但在整表验证时检查它们。GPU 最后三个占空比也会写入，不能因为这些地址在另一条握手协议中有别名就删去。

提交前先完整校验输入，关闭并验证 `0x07c6` bit 2，按掩码修改 `0x07c5` bit 7，然后写表、逐项读回、整表读回，再启用并重新核对。只改由本接口控制的位，保留同字节中的其他位。任何阶段失败都保留原始错误，另行记录恢复错误。

恢复使用接管前的原始字节，不从 OEM 的有损节点格式重新编码。旧表的奇数占空比、非 `255` 末项和其他旧值不会被新输入校验规则截断。恢复失败保留快照和 `RECOVERY_REQUIRED` 状态，并阻止其他控制器继续改写；尝试关停失败也必须明确报告，不能假定写入没有生效。

快照、读回和内核锁不等于固件原子操作或机械风扇验收。风扇实际响应、散热能力和声音都需要另测。

## 设备句柄与所有权

固定宽度接口位于 [uniwill_fan_curve_ioctl.h](../src/uniwill_fan_curve_ioctl.h)，不包含用户态指针，32 位和 64 位调用使用相同数据大小：

| 操作 | 大小 | 行为 |
| --- | ---: | --- |
| `GET_STATE` | 320 字节 | 读取所有权、错误和可用的原始状态；不申请控制权 |
| `ACQUIRE` | 64 字节 | 按设备生命周期和状态代次接管，保存原始表与驱动目标上下文 |
| `APPLY` | 160 字节 | 使用匹配的租约提交曲线，失败时恢复本次修改前的表 |
| `RESTORE_RELEASE` | 64 字节 | 恢复最初接管前的状态并释放控制权 |

写操作要求可写设备句柄和 `CAP_SYS_ADMIN`。接口初始只接受已查清布局的本机型号与 BIOS 组合；型号目录、品牌字符串和相似机型不会扩大写入权限。配置文件也不能授予设备支持能力。

一个打开的设备句柄持有一个租约。新接口在同一句柄内部串行处理，驱动还会阻止旧即时转速、AUTO、模式、功耗、调试写入及后台任务绕过接管。没有持有租约的其他句柄关闭时，不会触发恢复。

`dup` 和 `fork` 会延长内核文件描述的寿命，只有最后一个引用关闭才运行退出恢复。Rust 的 `Drop` 不能确认这次恢复是否成功；正常退出必须先显式恢复并检查结果。睡眠、移除和重新绑定使用设备生命周期代次，使旧句柄不能修改新生命周期的设备。失败的恢复快照需要保留，不能通过清空标志假装完成。

`RESTORED_VERIFIED` 是锁内完成恢复验证的事务回执。释放后 TCC 等控制器可能立即合法修改表，因此随后的 `GET_STATE` 实时表与旧表不同，不一定表示刚才的恢复失败。实时读失败使用独立的 `live_error`，不改写历史事务的 `last_error` 或 `restore_error`。回执同样不能证明风扇机械状态。

## 曲线文件与 CLI

开发版新增以下命令：

```sh
mechrevo-console fan validate --input curve.json
mechrevo-console fan hold --input curve.json
```

`validate` 只检查文件，不打开设备、不提权、不应用曲线。`hold` 是 Linux 前台控制进程，需要交互终端和支持新接口的驱动；按 Enter 后显式恢复并释放。强制结束后的内核恢复结果无法由已经退出的进程确认。它不会保存开机设置，也不会自动启动后台服务。

文件最多 8192 字节，UTF-8 JSON 的字段如下；所有字段必须存在，未知字段、重复字段、短数组、长数组、浮点数和越界值均拒绝：

| 字段 | 类型和含义 |
| --- | --- |
| `schema_version` | 整数 `1` |
| `layout` | 字符串 `uniwill_ram_fan1p5` |
| `respective` | 布尔值，选择 CPU/GPU 分别控制 |
| `cpu.rise_celsius` / `gpu.rise_celsius` | 各 15 个原始温度边界字节 |
| `cpu.fall_celsius` / `gpu.fall_celsius` | 各 15 个原始温度边界字节 |
| `cpu.duty_raw` / `gpu.duty_raw` | 各 16 个 `0..200` 整数，单位为半个百分点 |

前两个 CPU 升温边界不能同时为零，因为已恢复的启用协议不接受该条件。不额外编造 `DownT <= UpT` 或严格递增限制：查到的 OEM 表包含反例和重复 `255` 尾部。协议校验通过仍不代表温度边界、最低转速或停转策略适合这台电脑。

原始旧表与新输入是两种不同的数据，恢复不得通过 `curve.json` 绕一圈。这里也不提供根据相似型号猜出的默认曲线。

## 原生编辑器与授权进程

“风扇曲线”页使用真实的 16 档输出和 15 个升、降温边界，CPU/GPU 独立编辑；半个百分点的原始精度保留。草稿、校验后的预览、已确认应用的曲线分别保存。没有导入曲线时不填猜测的默认值，原始旧表也不会被自动转换成新输入。

普通检测使用只读设备句柄，不申请控制权。界面只在当前接口支持、状态新鲜且没有其他控制者时允许应用；旧驱动不支持接口时明确显示不可用。只有显式应用或需要授权的恢复操作才通过固定路径 `/usr/lib/mechrevo-console/fan-helper --serve` 请求管理员授权，整个界面仍以普通用户运行。

授权进程在一次界面会话内持有同一个设备句柄，使用有界 JSONL 通道接收类型化命令。协议不接受设备路径、后端选择、任意寄存器或通用命令。每个进程使用独立随机会话标识和单调请求编号。申请授权后先完成只读握手，再提交写入，避免把待执行的写入预先缓存在尚未批准的授权进程中。

客户端每 2 秒发送心跳；服务端在 20 秒没有完整有效请求后尝试显式恢复。坏帧、输入结束和输出断管也进入恢复。同步内核调用无法被此期限取消：调用阻塞时不能保证在 20 秒内恢复；返回后先处理过期状态，不把过期的应用报成成功。退出、断管和 `Drop` 都不能代替当前事务的恢复凭据。

界面后台检查进程的终态与实际回收结果，不为此循环读取 EC。关闭窗口会等待恢复和子进程回收；恢复失败时保留错误及重试入口。已经失去原进程、但驱动仍保有无主恢复快照时，显式恢复可以接管该快照用于恢复，不能借此应用新曲线。策略不自动跨睡眠重放，也不保存开机曲线。

后续源码为曲线控制期间增加独立的 hwmon 温度／RPM 采样，不再通过暂停全部读数来隔离写操作。它不枚举 OEM 控件、亮度、电源方案或目录；其他写入仍受原有会话互斥限制。热读数与完整设备信息分别记录采集时间，失败、暂停和超过常规间隔的旧值明确标出，趋势图不会跨长空窗直连。关闭自动采样不会关闭风扇心跳和退出恢复。内核传感器读取没有耗时上限，正在进行的读取可能延迟恢复任务与关闭，不能把只读调用说成可强制取消。此改动尚不属于 r163 安装包。

## 验证边界与后续工作

事务引擎测试编译真实生产头文件，使用模拟 EC 注入读取、写入、读回和回滚故障。独占、生命周期和设备句柄的测试需要分别通过真实 provider 和 ioctl 入口；旧测试中的“没有租约”兼容钩子只用于保留原有合同，不能充当租约测试。

Rust 测试覆盖严格输入、固定布局、持有与释放、错误对账、前台进程清理、代理协议、子进程退出、界面关闭和真实布局交互。这些都是离线测试，不替代安装、加载、风扇响应、长时间温控或声音验收。

后续仍需要休眠后的策略恢复、Windows 传输层及实机验收。当前会话 helper 不等于开机常驻服务。风扇异响需要结合转速和录音继续定位，不能用这些接口测试通过来宣布降噪成功。
