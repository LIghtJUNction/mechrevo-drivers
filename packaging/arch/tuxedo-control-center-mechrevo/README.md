## pkgrel3 readback and diagnostics candidate

The third patch rejects non-number, non-finite or out-of-range speed readback. The worker preserves the existing `-1` unavailable sentinel and accepts finite percentages in `0..100`, including fractions. A failed write followed by valid readback still publishes that actual readback, rather than the requested target; this is not mechanical RPM or curve acknowledgement. Multiple original failures survive hostile string conversion, and formatting cannot rethrow from the outer worker error log.

The real unchanged Hwmon backend reproduces a zero denominator when fanMax is zero. Without the guard, NaN becomes JSON null. With D-Bus available and a positive timestamp, the existing frontend can treat null as valid and format it as 0%; the new unavailable sentinel selects N/A for CPU fan text. This is a conditional source conclusion, not a rendered GUI test or gauge-pointer claim.

An old reload could instead retain and overwrite with its prior settings. Both synchronous and asynchronous settings reads validate the types of present fields before consumers use them; for example, the string `"false"` is rejected instead of acting as true. Only `ENOENT` permits creation of defaults. Valid older settings with missing fields still use the existing migration, including the existing default `fanControlEnabled=true` when that field is absent. Unknown extension fields are retained. Keyboard members are checked only when present, preserving white-only devices that omit RGB values; this is a present-field guard rather than a complete schema or device-specific range policy.

The daemon separates read failures from migration and preserves the accumulated dirty flag when output-port synchronization returns false.
