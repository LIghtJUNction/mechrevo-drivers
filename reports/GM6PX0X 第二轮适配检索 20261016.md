## NVIDIA：ASPM 与运行时 D3 必须分开排查

只读核对当前运行状态：NVIDIA open 615.78.08，`DynamicPowerManagement: 3`，
GPU `power/control=auto`，驱动 power 文件报告 `Enabled (fine-grained)`。
本机之前已确认 ASPM Disabled，但 ASPM 与运行时 D3 是不同机制；前者关闭不能排除后者。
当前 `runtime_status=active` 是失联后的状态，不能反推故障前是否发生 D3 切换。

NVIDIA 615.78.08 官方文档说明，支持的 Ampere 及后续笔记本中默认值 0x03
对应细粒度运行时省电；0x00 禁用运行时 D3，显卡保持供电，可能增加空闲功耗。
这提供一个有官方语义的隔离变量，不是本机根因结论或已经验证的修复。

- [615.78.08 RTD3 文档](https://download.nvidia.com/XFree86/Linux-x86_64/615.78.08/README/dynamicpowermanagement.html)
- [Linux 运行时电源管理机制](https://docs.kernel.org/power/runtime_pm.html)

issue #1064 不是只有 Blackwell：RTX 4060 用户也报告了混合模式下的 GSP 心跳错误，
但该用户当时明确表示桌面／游戏没有明显异常，因此不能写成其 RTX 4060 已复现 Xid 79。
主报告者的 GSP／DIFR 问题更复杂：后续报告显示 610.43.02 在 DPM=0x00 下仍出现
DIFR 锁死；615.71.09 也仍可复现，且 nvidia-smi 在这种锁死期间保持可响应。
它与本机 nvidia-smi 不可访问、PCIe UnsupReq、Xid 79 的故障签名不相同。

- [RTX 4060 原始评论](https://github.com/NVIDIA/open-gpu-kernel-modules/issues/1064#issuecomment-4128173802)
- [关闭 DPM 后仍锁死的后续记录](https://github.com/NVIDIA/open-gpu-kernel-modules/issues/1064#issuecomment-4743236435)
- [615.71.09 后续记录](https://github.com/NVIDIA/open-gpu-kernel-modules/issues/1064#issuecomment-5663616226)

用户报告的局部 DIFR 禁用补丁不能当作本机 Xid 79 修复，不据此修改 NVIDIA 源码。
同样不能在 open 模块上只设置 EnableGpuFirmware=0 就宣称已关闭 GSP；
官方 open 模块 README 明确要求配套 GSP 固件。

- [615.78.08 源码 README](https://github.com/NVIDIA/open-gpu-kernel-modules/blob/ca2d03e6fafd4d4b56b383497d931c25b283bfcf/README.md)

## 对照本机故障前记录

检索当前启动、截至 2026-10-15 23:28:24 的 1490 行内核日志：未找到 GSP 心跳超时、
0x101a、BAR1 VA 分配失败、NV_ERR_NO_MEMORY、AE_AML_LOOP_TIMEOUT、
nvWriteGpEntry 或 Enabling HDA controller 特征。普通看门狗的 heartbeat=30 不是 GSP 心跳。
未出现这些日志不排除对应机制，但目前不能把本机归入上述已报告路径。

本机故障窗口有 root port 8086:460d 的 Transaction Layer／UnsupReq，
GPU 及 HDA 均报告无 error_detected 回调，随后恢复失败并要求 OS Reboot。
不能单凭 UnsupReq 判定硬件损坏、GSP 固件或供电是根因。

另有 615.71.09／RTX 3060 报告在 BAR1 VA 分配失败后失联；报告者也明确区分先后，
认为失联后的 GSP 错误可能只是结果。本机未找到其前置错误，不采用其机制解释。

## 键盘与错误匹配排除

找到 PCSpecialist GM6PX0X 的原始 inxi 记录，确实包含 ITE 8291、USB 048d:ce00。
本机本轮 lsusb 未枚举任何 048d 设备。说明同板号不同品牌／配置的键盘控制器不能互相推定，
不能据这个样本开放本机逐键控制，也不能据缺少 USB ID 宣称硬件永远不支持逐键。

- [PCSpecialist 原始硬件记录](https://forum.manjaro.org/t/after-update-3rd-display-is-not-working/176043)

搜索命中的 Semcosm/win_HardwareConsole 当前仍是 mock UI 原型，
README 明确说明风扇、功耗等不写真实硬件。它不是新的已验收 GM6PX0X 控制实现。

- [固定提交的项目说明](https://github.com/Semcosm/win_HardwareConsole/blob/eab88225284020d7acce6430296909f55a2058a0/README.md)

## 下一步的执行边界

1. 保留用户暂不重启的决定。显卡未恢复时不解绑、不复位、不尝试省电切换。
2. 手动重启恢复后，先保持当前配置验证正常可访问，再记录运行时状态与故障前日志。
   研究空闲 D3 进出时不能高频运行 nvidia-smi；现有温度观测器会唤醒独显，不能作为无干扰的 D3 对照。
3. 若数据支持运行时省电方向，再单独测试禁用 D3；不要同时降级驱动、改 PL1／PL2、风扇和 BIOS。
   这是待执行的隔离实验，不在本轮写入默认配置。
4. 固件方向继续需要官方 MRO13 下载包、精确型号／CPU／EC 适用说明及恢复材料。
   已知 MRO13 身份记录不足以刷写，GM6PQ7X／MRO16 和其他品牌固件也不替代它。
